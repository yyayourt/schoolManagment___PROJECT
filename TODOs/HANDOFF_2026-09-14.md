## 5. Repères pour reprendre le code

- **Auth & rôle** : `utils/roles.js` → `getAuthAndRole` ; `app/api/lib/familyScope.js` →
  `requireFamilyScope(request, { staffOnly | adminOnly })` renvoie `{ auth, allowedStudentIds, isStaff, schoolKey }`.
- **École courante** : **jamais** lire le cookie `x-school-key` dans une route. Utiliser
  `scope.schoolKey` (familyScope), `ctx.schoolKey` (withAuth) ou `await resolveSchoolKey()`.
  Règle pure : `app/api/lib/schoolScopeRules.js`.
- **Démo / prod** : `isSandboxRequest()` (`app/api/lib/tenant.js`) = seul discriminant côté serveur.
  Tout compromis de démo doit être conditionné par lui, jamais par un cookie.
- **Thème** : `utils/themeSanitizer.js`, appliqué à l'écriture (`PUT /api/school_ai/ecole`) et à
  l'injection (`app/Home.jsx`).
- **Tests** : `npm run test:unit` (règles pures, `tests/unit/*.unit.mjs`) ; `npm run test:e2e` (Playwright,
  mode `NEXT_PUBLIC_MODE=test` : le cookie d'école y fait foi, ne teste pas la règle prod).
- **Audit d'auth** : un grep doit inclure `withAuth` et `checkRole` en plus de
  `getAuthAndRole|requireAuth|requireFamilyScope|authWithFallback`, et vérifier que l'import est
  **appelé** (cas `sync-user`).
